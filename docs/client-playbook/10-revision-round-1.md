# 10 — Revision Round 1

## Goal

Resolve the customer's first round of requested changes efficiently — this project
includes two revision rounds, and round 1 is the first of them.

## Owner Tasks

- Read the structured revision request (area + description) the customer submitted.
- Make the requested changes.
- Once done, move the project back to Customer Review so the customer can see the result and decide again (approve, or use round 2 if something is still off).
- Resolve the revision request record once the change is live.

## Customer Tasks

- When requesting: describe each change separately (not one long paragraph covering five things) so each one can be tracked and resolved individually.
- The portal shows an info note before submitting: *"This project includes up to two revision rounds if needed. We recommend collecting all requested changes together so we can complete them efficiently."* — encourage the customer to list everything they want changed in this one round rather than trickling in requests one at a time.
- After the round is submitted, a "Revision Round 1" label appears on their portal — this is the first time revision rounds are mentioned to them at all.

## Checklist

- [ ] Every item in the customer's round 1 request has been addressed, not just the first one mentioned.
- [ ] The revision request record is marked resolved with a clear resolution note.
- [ ] The project is back in Customer Review for the customer to see the result.

## Exit Criteria

Round 1's changes are live and the customer is reviewing again. If they approve, go to
[12 Final Approval](./12-final-approval.md). If they need more changes, go to
[11 Revision Round 2](./11-revision-round-2.md).
